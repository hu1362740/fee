# PM2 知识库与本项目使用说明

> 适用项目：`fee-pro`  
> 适用读者：不了解 PM2，但需要维护、部署或排查本项目 Node.js 服务的开发者  
> 相关文件：`server/pm2_fee_app.json`、`server/pm2_fee_task_manager.json`

---

## 一、PM2 是什么

PM2 是 Node.js 生态中常用的**进程管理器**。它的核心作用是：把 Node.js 程序当作长期运行的后台服务来管理。

平时在开发机上启动一个 Node 服务，常见写法是：

```bash
node dist/app.js
```

或者：

```bash
npm run dev
```

这种方式适合本地调试，但有几个问题：

- 终端关闭后，进程会退出。
- 服务器重启后，进程不会自动恢复。
- 程序异常退出后，需要人工重新启动。
- 查看日志、重启服务、管理多个 Node 进程不够方便。
- 测试环境和生产环境需要更稳定、更可观察的运行方式。

PM2 就是为了解决这些问题而出现的。它会在后台维护一个 PM2 守护进程，由这个守护进程负责启动、停止、重启、监控和保存 Node.js 应用的运行状态。

可以把 PM2 理解为：

```text
人工在终端运行 node
        ↓
PM2 在后台替你长期管理 node 进程
```

---

## 二、PM2 的主要作用

### 2.1 后台运行进程

使用 PM2 启动后，即使当前 SSH 会话或终端窗口关闭，Node.js 程序仍然可以在后台运行。

```bash
pm2 start dist/app.js --name fee-app
```

### 2.2 进程异常自动重启

如果 Node.js 程序因为未捕获异常、内存问题或其他错误退出，PM2 可以自动重新拉起进程，减少服务中断时间。

### 2.3 统一查看进程状态

PM2 可以列出当前管理的所有进程，包括名称、进程 ID、运行时间、重启次数、CPU、内存等信息。

```bash
pm2 list
pm2 status
```

### 2.4 统一查看日志

PM2 会收集标准输出和错误输出，也支持把日志写到指定文件。

```bash
pm2 logs
pm2 logs fee-app
```

### 2.5 支持开机自启动

在 Linux 服务器上，PM2 可以配合 systemd 生成开机自启动配置。服务器重启后，PM2 会恢复之前保存的进程列表。

```bash
pm2 startup
pm2 save
```

### 2.6 支持环境变量和配置文件

PM2 支持通过配置文件声明脚本路径、工作目录、启动参数、日志路径和不同环境下的环境变量。

本项目就使用了两个 PM2 配置文件：

```text
server/pm2_fee_app.json
server/pm2_fee_task_manager.json
```

### 2.7 支持监听文件变化后重启

PM2 可以开启 `watch`，当指定目录文件变化时自动重启进程。

本项目配置中监听的是 `server/dist`：

```json
"watch": [
  "dist"
]
```

这意味着修改 `server/src` 后，只有先通过 Babel 编译到 `dist`，PM2 才能感知到运行代码变化。

## 三、PM2 不是什么

理解 PM2 时，也要明确它的边界。

PM2 不是 Node.js 本身。Node.js 负责执行 JavaScript 程序，PM2 负责管理 Node.js 进程。

PM2 不是 Nginx。Nginx 常用于反向代理、静态资源服务、负载均衡、日志收集；PM2 负责拉起和管理 Node 后端进程。

PM2 不是数据库或缓存。它不替代 MySQL、Redis、Kafka。

PM2 不是代码编译工具。本项目服务端实际运行 `server/dist`，仍然需要先执行：

```bash
npm run build
```

或者保持：

```bash
npm run watch
```

PM2 也不是业务调度器。本项目的业务定时任务由 `Task:Manager` 内部的 `node-schedule` 执行；PM2 只是保证 `Task:Manager` 这个 Node 进程长期活着。

## 四、PM2 在哪些平台使用

PM2 本身是 Node.js 工具，可以安装在 Node.js 支持的平台上，包括 Linux、macOS 和 Windows。

但不同平台的推荐程度不同：

| 平台 | 是否可用 | 推荐场景 | 说明 |
|------|----------|----------|------|
| Linux | 可用，最常见 | 测试环境、生产环境 | 最推荐。服务器部署、开机自启动、日志管理都比较成熟 |
| macOS | 可用 | 本地模拟部署、个人调试 | 可用于学习和临时验证，一般不是正式部署环境 |
| Windows | 可用 | 本地开发、临时测试 | 能运行，但开机自启动和服务化管理不如 Linux 自然；本项目 Windows 开发更建议用 npm 脚本 |

在企业服务端部署中，PM2 最常见的使用平台是 Linux，例如 CentOS、Ubuntu、Debian。

## 五、PM2 的适用场景

### 5.1 适合使用 PM2 的场景

- Node.js Web API 需要长期运行。
- 后台任务进程需要长期运行。
- 测试环境、预发环境、生产环境需要稳定守护进程。
- 希望服务异常退出后自动重启。
- 希望统一管理多个 Node 进程。
- 希望统一查看日志和运行状态。
- 服务器重启后，希望服务自动恢复。

### 5.2 不一定需要 PM2 的场景

- 本地开发阶段，只是临时调试接口。
- 需要频繁修改源码、断点调试。
- 前端开发服务器，例如 `client` 的 `npm run dev`。
- 一次性脚本，例如临时执行某个 `npm run fee Parse:Monitor ...` 命令。

本地开发时，`nodemon`、`npm run watch`、IDE 调试器通常比 PM2 更直观。

## 六、PM2 常用命令

### 6.1 安装

```bash
npm install -g pm2
```

Linux 服务器上如果需要全局安装，可能会看到：

```bash
sudo npm install -g pm2
```

### 6.2 启动进程

直接启动脚本：

```bash
pm2 start dist/app.js --name fee-app
```

使用配置文件启动：

```bash
pm2 start pm2_fee_app.json --env testing
```

### 6.3 查看进程

```bash
pm2 list
pm2 status
pm2 show fee-app
```

### 6.4 查看日志

```bash
pm2 logs
pm2 logs fee-app
pm2 logs fee-task-manager
```

### 6.5 重启、停止、删除

```bash
pm2 restart fee-app
pm2 stop fee-app
pm2 delete fee-app
```

### 6.6 保存进程列表与开机自启动

```bash
pm2 startup
pm2 save
```

`pm2 startup` 会根据当前系统生成一条需要执行的命令。通常要复制它输出的命令再执行一次。

`pm2 save` 会保存当前 PM2 进程列表。机器重启后，PM2 会按这个列表恢复进程。

## 七、本项目中 PM2 是做什么用的

本项目服务端不是只有一个 Node 进程，而是至少包含两个长期运行的进程：

| PM2 进程名 | 配置文件 | 入口 | 作用 |
|-----------|----------|------|------|
| `fee-app` | `server/pm2_fee_app.json` | `server/dist/app.js` | 启动 Express Web 服务，提供 API 和静态页面服务 |
| `fee-task-manager` | `server/pm2_fee_task_manager.json` | `server/dist/fee.js Task:Manager` | 启动任务调度主进程，定时保存日志、解析数据、汇总统计、触发报警 |

也就是说：

```text
fee-app
  负责对外提供 Web/API 服务

fee-task-manager
  负责后台数据处理和周期性任务
```

这两个进程都很重要。

如果只启动 `fee-app`，前端页面和 API 可能能访问，但日志保存、数据解析、统计汇总、报警等后台任务不会完整运行。

如果只启动 `fee-task-manager`，后台任务可能在跑，但没有 Web API 对外提供服务。

完整部署时通常两个都要启动。

## 八、本项目 PM2 配置详解

### 8.1 `pm2_fee_app.json`

文件位置：

```text
server/pm2_fee_app.json
```

核心配置：

```json
{
  "name": "fee-app",
  "script": "./dist/app.js",
  "cwd": "./",
  "watch": [
    "dist"
  ],
  "error_file": "./log/pm2/app/app-err.log",
  "out_file": "./log/pm2/app/app-out.log",
  "env": {
    "NODE_ENV": "development"
  },
  "env_production": {
    "NODE_ENV": "production"
  },
  "env_testing": {
    "NODE_ENV": "testing"
  }
}
```

含义说明：

| 字段 | 含义 |
|------|------|
| `name` | PM2 中显示的进程名称 |
| `script` | 要执行的 Node.js 入口文件 |
| `cwd` | 进程工作目录，这里表示 `server` 目录 |
| `watch` | 监听 `dist` 目录变化，变化后自动重启 |
| `ignore_watch` | 忽略 `node_modules`、`log` 等目录 |
| `error_file` | 错误日志输出位置 |
| `out_file` | 普通日志输出位置 |
| `env` | 默认环境变量 |
| `env_testing` | 使用 `--env testing` 时的环境变量 |
| `env_production` | 使用 `--env production` 时的环境变量 |

这个进程启动的是：

```bash
node ./dist/app.js
```

它对应源码入口：

```text
server/src/app.js
```

主要负责：

- 启动 Express。
- 监听 `server/src/configs/app.js` 中配置的端口，默认 `3000`。
- 提供 `/api/*` 和 `/project/:id/api/*` 接口。
- 提供构建后的前端静态页面。
- 处理前端 history 路由 fallback。

### 8.2 `pm2_fee_task_manager.json`

文件位置：

```text
server/pm2_fee_task_manager.json
```

核心配置：

```json
{
  "name": "fee-task-manager",
  "script": "./dist/fee.js",
  "cwd": "./",
  "args": ["Task:Manager"],
  "watch": [
    "dist"
  ],
  "error_file": "./log/pm2/command/task-manager-err.log",
  "out_file": "./log/pm2/command/task-manager-out.log"
}
```

这个进程启动的是：

```bash
node ./dist/fee.js Task:Manager
```

它对应源码入口：

```text
server/src/fee.js
server/src/commands/task/manage.js
```

主要负责启动 `Task:Manager`，然后由 `node-schedule` 注册定时任务。

本项目 `Task:Manager` 会周期性执行：

| 周期 | 主要任务 |
|------|----------|
| 每 1 分钟 | 保存 Nginx/Kafka 日志、分割日志、报警检测、解析错误日志、汇总错误数据 |
| 每 10 分钟 | 更新缓存、解析 UV/停留时长/性能/错误数据、汇总小时级数据 |
| 每 1 小时 | 解析设备、菜单点击、新用户数据，汇总当天数据 |
| 每 6 小时 | 汇总昨日和月度数据，统计浏览器/设备/系统分布，清理旧日志 |

因此，`fee-task-manager` 是本项目数据链路能够持续运转的关键进程。

## 九、开发、测试、生产环境是否都需要 PM2

结论先说：

| 环境 | 是否需要 PM2 | 推荐程度 | 说明 |
|------|--------------|----------|------|
| 开发环境 | 不一定需要 | 低 | 本地开发优先用 `npm run watch`、`npm run dev`、`npm run fee Task:Manager` |
| 测试环境 | 建议使用 | 高 | 测试服务器需要模拟长期运行状态，PM2 便于守护和排查 |
| 生产环境 | 推荐使用 | 很高 | 需要进程守护、自动重启、日志管理、开机恢复 |

### 9.1 开发环境

开发环境的主要目标是快速修改、快速重启、方便调试。

本项目服务端源码在 `server/src`，实际运行在 `server/dist`。开发时通常需要两个终端：

```bash
cd server
npm run watch
```

```bash
cd server
npm run dev
```

如果要调试后台任务，再启动：

```bash
cd server
npm run fee Task:Manager
```

开发环境一般不强依赖 PM2，原因是：

- 本地经常需要看实时编译输出。
- 本地经常需要临时停止、断点调试或修改配置。
- 使用 `nodemon` 已经能满足开发期自动重启。
- Windows 本地开发时，`Task:Manager` 内部的防重逻辑依赖 Linux `ps` 命令，无法完整发挥作用。

如果开发者想在本机模拟服务器部署，也可以使用 PM2：

```bash
cd server
npm run build
pm2 start pm2_fee_app.json --env development
pm2 start pm2_fee_task_manager.json --env development
```

但这更适合作为部署演练，不是日常开发必需步骤。

### 9.2 测试环境

测试环境通常部署在 Linux 服务器上，需要长期提供服务给测试人员或业务方验证。

测试环境建议使用 PM2，因为它可以：

- 保证 `fee-app` 和 `fee-task-manager` 长期运行。
- 记录服务日志，方便排查问题。
- 在进程异常退出后自动重启。
- 使用 `--env testing` 加载测试环境配置。
- 模拟生产环境的运行方式。

测试环境常用命令：

```bash
cd server
npm run build
pm2 start pm2_fee_app.json --env testing
pm2 start pm2_fee_task_manager.json --env testing
pm2 list
pm2 logs
```

如果配置或代码更新后需要重启：

```bash
cd server
npm run build
pm2 restart fee-app --update-env
pm2 restart fee-task-manager --update-env
```

### 9.3 生产环境

生产环境推荐使用 PM2。

生产环境的核心目标是稳定、可恢复、可观测。PM2 可以提供：

- 进程守护。
- 异常自动重启。
- 日志管理。
- 开机自启动。
- 多进程统一管理。
- 部署后手动或自动重启。

生产环境常用命令：

```bash
cd server
npm run build
pm2 start pm2_fee_app.json --env production
pm2 start pm2_fee_task_manager.json --env production
pm2 save
```

首次配置开机自启动：

```bash
pm2 startup
pm2 save
```

生产环境更新代码后，通常流程是：

```bash
cd server
npm install --production
npm run build
pm2 restart fee-app --update-env
pm2 restart fee-task-manager --update-env
pm2 save
```

如果前端由 `server` 一体化提供，还需要在 `client` 下构建前端产物，并按项目部署方案放到对应静态资源目录。

## 十、本项目三种环境的差异

本项目通过 `NODE_ENV` 区分环境：

```text
development
testing
production
```

PM2 配置文件中提供了三套环境变量：

```json
"env": {
  "NODE_ENV": "development"
},
"env_testing": {
  "NODE_ENV": "testing"
},
"env_production": {
  "NODE_ENV": "production"
}
```

启动时通过 `--env` 指定：

```bash
pm2 start pm2_fee_app.json --env testing
pm2 start pm2_fee_app.json --env production
```

差异主要体现在 `server/src/configs/` 中读取不同配置，例如：

- `server/src/configs/app.js`
- `server/src/configs/common.js`
- `server/src/configs/mysql.js`
- `server/src/configs/redis.js`
- `server/src/configs/kafka.js`
- `server/src/configs/alarm.js`

需要注意的是，当前项目中部分配置的 `testing`、`production` 直接复用了 `development` 或默认配置。实际部署前应根据环境检查：

- MySQL 地址、账号、密码和数据库名。
- Redis 地址和密码。
- Kafka 是否启用。
- Nginx 日志路径。
- 报警开关和报警接收人。
- `app.js` 监听端口。
- 是否需要修改硬编码 salt 等安全配置。

这是用 PM2 启动 Web 服务。

适合：

- 测试环境。
- 生产环境。
- 模拟正式部署。

### 11.4 `pm2 start pm2_fee_task_manager.json`

这是用 PM2 启动后台任务调度进程。

适合：

- 测试环境。
- 生产环境。
- 需要后台任务持续运行的长期环境。

本项目还会通过 `log4js` 输出自己的业务日志，常见位置为：

```text
server/log/
```

PM2 日志主要回答“进程有没有启动、有没有报错退出”；项目业务日志主要回答“任务有没有执行、数据有没有处理成功”。

本项目 PM2 监听的是 `dist`，而不是 `src`。

如果只改了：

```text
server/src/
```

但没有重新编译到：

```text

```

解决方式：

```bash
cd server
npm run build
pm2 restart fee-app
pm2 restart fee-task-manager
```

或者开发环境保持：

```bash
npm run watch
```

## 十四、常见误区

### 14.1 误区：用了 PM2 就不需要 Nginx

不对。

PM2 管 Node 进程，Nginx 负责反向代理、静态资源、访问日志等。两者职责不同。

本项目 SDK 日志链路还可能依赖 Nginx access log，因此不能简单用 PM2 替代 Nginx。

### 14.2 误区：用了 PM2 就不需要 `npm run build`

不对。

PM2 只运行 `dist` 中的文件。本项目服务端源码改动后必须编译。

### 14.3 误区：只启动 `fee-app` 就完整了

不对。

`fee-app` 只是 Web 服务。后台数据处理需要 `fee-task-manager`。

### 14.4 误区：PM2 就是定时任务系统

不准确。

本项目的定时任务由 `Task:Manager` 内部的 `node-schedule` 注册。PM2 只是守护 `Task:Manager` 进程。

### 14.5 误区：开发环境必须使用 PM2

不需要。

开发环境优先使用 `npm run watch`、`npm run dev` 和直接执行 `npm run fee ...`。PM2 更适合服务器环境和部署验证。

---

## 十五、简短结论

PM2 是 Node.js 进程管理器，主要用于让 Node 程序在服务器上稳定、长期、可恢复地运行。

在本项目中，PM2 主要管理两个服务端进程：

- `fee-app`：Web/API 服务。
- `fee-task-manager`：后台任务调度服务。

开发环境可以不用 PM2；测试环境建议用 PM2；生产环境推荐用 PM2，并配合 `pm2 startup`、`pm2 save` 做开机自启动和进程恢复。

维护本项目时要记住一句话：

```text
PM2 管进程，Task:Manager 管任务，Nginx 管入口和日志，MySQL/Redis/Kafka 管数据链路。
```
