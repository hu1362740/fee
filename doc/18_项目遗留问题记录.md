## 1. server 依赖中的 `sqlite3` 可能是历史遗留

记录日期：2026-07-20

### 问题背景

`server/package.json` 中声明了：

```json
"sqlite3": "^4.0.4"
```

但项目整体设计和现有实现都以 MySQL 为主。SQLite 和 MySQL 都属于关系型数据库，都会使用 SQL，但形态不同：

- SQLite 通常是一个本地 `.db` 文件，不需要单独启动数据库服务，适合单机、小工具、测试或本地缓存等场景。
- MySQL 是独立数据库服务，适合 Web 服务、多人访问和生产环境的高并发读写场景。
- npm 包 `sqlite3` 不是数据本身，而是 Node.js 访问 SQLite 数据库的原生驱动包。
- npm 包 `mysql` 是 Node.js 访问 MySQL 数据库的驱动包。

### 当前结论

从当前源码看，`sqlite3` 没有被业务代码使用，较大概率是历史遗留依赖。

已确认的线索：

- `server/package.json` 中存在直接依赖：`"sqlite3": "^4.0.4"`。
- 排除 `node_modules` 和 `dist` 后，业务源码中没有发现 `import sqlite3`、`require('sqlite3')` 或 `client: 'sqlite3'`。
- 服务端数据库连接层 `server/src/library/mysql/index.js` 使用的是 `knex`，并明确配置 `client: 'mysql'`。
- 服务端 MySQL 配置位于 `server/src/configs/mysql.js`，开发、测试、生产环境分别配置 `platform`、`platform_test`、`platform_prod`。
- 服务端测试文件 `server/src/test/mocha_test.js` 中的 Knex 示例也使用 `client: 'mysql'`。

因此，当前项目并不是“因为使用 Knex 就必须安装 sqlite3”。Knex 支持多种数据库，具体使用哪一种取决于 `client` 配置；本项目配置的是 MySQL。

### Node 22 安装风险

`sqlite3@4.x` 是较老的 native 原生扩展包。它安装时通常会先尝试下载与当前操作系统、CPU 架构、Node ABI 匹配的预编译二进制文件；如果下载不到或不匹配，会回退到 `node-gyp` 本地编译。

在 Node.js `v22.16.0` 下，`sqlite3@4.x` 存在兼容和安装风险：

- `^4.0.4` 并不是锁死 `4.0.4`，而是允许安装 `>=4.0.4 <5.0.0` 的版本；当前 Windows 环境实际安装到的是 `sqlite3@4.2.0`。
- Windows 下 `npm i` 成功，只能说明当前机器已经成功下载或编译出了 `node-v127-win32-x64` 绑定，不能证明 Ubuntu 下也一定成功。
- 阿里云 Ubuntu + Node.js `v22.16.0` + npm 10 的干净环境中，可能因为找不到 `node-v127-linux-x64` 预编译包、网络访问二进制源失败、缺少 `python` / `make` / `g++` / `build-essential`，或旧源码不适配 Node 22，导致 `npm i` 失败。
- `npm run build` 能成功只能说明 Babel 编译通过，不代表 `sqlite3` 原生模块在运行时一定可加载。

### 影响范围

如果继续保留该依赖：

- 部署到 Ubuntu 或 CI 环境时，`npm i` 可能因为 `sqlite3` 安装失败而阻塞。
- 即使业务代码不用 SQLite，也会因为它是直接依赖而被 npm 安装。
- 这个风险与项目实际 MySQL 功能无关，属于额外的安装维护成本。

### 处理建议

建议移除 `server/package.json` 中的 `sqlite3` 依赖。

推荐验证步骤：

```bash
cd server
npm uninstall sqlite3
npm run build
```

如果后续有测试环境，可继续验证：

```bash
cd server
npm test
```

如果因为缺少 MySQL、Redis、Nginx 或其他基础服务导致测试无法完整执行，应在验证记录中说明限制。

### 后续注意

如果未来确实新增 SQLite 使用场景，应重新评估依赖版本，而不是继续使用 `sqlite3@4.x`。优先考虑升级到兼容现代 Node.js 的 `sqlite3@5.x` 或其他维护状态更明确的 SQLite 驱动，并同步补充使用位置、配置说明和部署验证记录。
